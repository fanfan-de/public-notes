# 如何为 Agent 选择文件工作区

如果 Agent 要读代码、修改草稿或运行脚本，可以给它一个普通目录，例如 `/workspace`。Agent 的文件工具和脚本都通过这个目录读写项目文件。选择底层存储时，先确定任务结束后哪些文件还要保留，以及下一次执行任务的机器怎样找到它们。

## 按任务选存储

| Agent 怎么工作 | 可以怎么存 | 下次如何取回 |
| --- | --- | --- |
| 固定在一台云服务器上，多轮编辑同一项目 | 在持久云硬盘上按项目建目录。如果用容器运行，就把项目目录或持久卷挂载到容器里 | 新容器启动时挂回原来的目录或卷，Agent 继续按熟悉的路径打开文件 |
| 任务可能分配给不同机器，每台机器都要直接读写同一份项目文件 | 把云文件存储（NAS）挂载到各台执行机器上 | 执行机器切换后，新的机器通过共享目录读取已有文件 |
| 每个任务独立处理一份输入，例如录音转写 | 输入和成品放在对象存储，需要运行工具时用临时目录处理 | 记录输入和成品的对象键，确认成品上传成功后即可释放临时目录 |

持久卷可以在容器重建后继续使用。若采用 Docker 默认的本地卷，卷位于创建它的主机上。换到另一台主机时，即使创建同名卷，也不会自动得到原文件。NAS 适合多台机器共享同一目录。如果多个 Agent 还要同时修改同一个文件，可以安排一个负责合并的写入者，或通过文件锁协调写入。[Docker 持久卷文档](https://docs.docker.com/engine/storage/volumes/) · [阿里云文件存储 NAS 文档](https://help.aliyun.com/zh/nas/product-overview/what-is-nas)

## 怎样让 Agent 明天接着写报告？

第一天，Agent 读取 `资料.csv`，把前两节写进 `草稿.md`。暂停时，它在同一目录的 `进度.md` 里记下当天的进度和下一步。

> 前两节已完成。下一步用资料表中的退款记录核对第三节，再导出 PDF。

第二天，新会话挂回这个项目目录，先读进度，再打开草稿和资料表。持久目录保留了文件，进度记录说明了下一步该做什么。定稿后，如果读者只需要下载，可以把 `报告.pdf` 上传到对象存储，草稿继续留在工作目录里。[Amazon S3 用户指南](https://docs.aws.amazon.com/zh_cn/AmazonS3/latest/userguide/Welcome.html)

对于先部署在单台服务器上的 Agent，**一块持久云硬盘、每个项目一个目录**就是简单的起点。以后出现跨机器接手同一目录的需求，再考虑 NAS。只需收附件、交成品的独立任务，则可以直接采用对象存储和临时目录。
