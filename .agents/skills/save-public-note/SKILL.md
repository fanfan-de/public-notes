# 保存公开笔记

将用户选定的内容整理到 [fanfan-de/public-notes](https://github.com/fanfan-de/public-notes)，遵循目标仓库的公开内容边界。调用时的项目可以是另一个仓库。

## 找到目标仓库

从本 Skill 所在位置运行 [scripts/resolve_vault.py](scripts/resolve_vault.py)，使用脚本返回的绝对目录作为目标。脚本通过真实文件位置和 Git 远程验证定位，不依赖当前工作目录，也不在 Skill 中写死本机路径。

本机的全局入口是指向目标仓库中此 Skill 的软链接。若入口失效，或脚本不能确认目标，让用户在正确的 public-notes 克隆中运行 `python3 scripts/setup.py` 修复。不要把笔记退而写进当前项目，也不要自行克隆或公开其他仓库。

先读取目标仓库的 `AGENTS.md` 和根 `README.md`，后续文件操作针对该目录，Git 命令显式指定该目录。遵守当前环境的文件访问权限。

## 整理并保存

- 使用用户明确选定的材料，例如“当前讨论”“这篇文章”或指定文件。用户只要求摘要、没有要求保存时，不创建笔记。
- 写入前整理成可公开的知识：提炼背景、结论、依据、适用范围和待验证问题；删除隐私、个人生活、密钥、私人对话细节、本机路径及未公开的项目或他人信息。不要先把原始材料暂存到公开仓库再清理。
- 如果有价值的内容依赖无法确认可公开的信息，先提出一个具体问题或提供可公开的提纲，不把不确定的原文写入仓库。用户已明确授权的公开内容不重复请求确认。
- 保留可公开且可核实的原始来源，区分事实、推断和实际观察，不把生成内容写成用户的亲身经历。时效性事实按需要查证。
- 先搜索相近笔记，选择新增或补充已有笔记，保留用户现有改动。优先选择已有根目录分类；新主题直接增加同级分类，内容不确定时放 `收集/`，不增加无必要的子目录。
- 采用中文 Markdown、简短属性和相对链接，按内容需要参考目标仓库 `模板/` 中的模板。保留用户指定的标题和文件名，避免重复笔记。
- 以文本和 Mermaid 为主，大材料链接到公开原始来源，不复制大图片。复杂或含反斜杠的正文直接用文件工具写入；需要移动已有笔记时按目标仓库约定使用 Obsidian CLI 更新链接。

## 检查与同步

写入后检查本次文件的内容、相对链接和 1 MiB 文件限制。对实际写入的文件运行 Gitleaks 文件扫描，使用目标仓库 `.gitleaks.toml` 和 `--redact`；不要仅运行暂存区检查就宣称未暂存的新笔记已检查。

例如，先把解析出的目录和本次笔记绝对路径分别赋给 `notes_root`、`note_path`，再运行：

```bash
gitleaks dir --config "$notes_root/.gitleaks.toml" --redact --no-banner "$note_path"
```

若未安装 Gitleaks，在目标仓库运行 `python3 scripts/setup.py` 安装；检查失败时修正本次内容，不能绕过检查。不要输出扫描发现的敏感原文。

保存笔记本身不隐含推送到公开 GitHub。用户已授权提交、同步或发布时，遵循目标仓库 Git 流程，只暂存本次笔记和必要导航改动，检查差异、运行仓库检查后提交推送；否则保留本地文件，不顺带提交其他改动。

完成时给出实际笔记的可点击路径、简短内容说明，以及本地保存或已同步 GitHub 的准确状态。
